# keen-docs

An Elixir/Phoenix **docs + showcase engine** for KeenMate's component libraries — the "done
better" rewrite of `../svelte-docs`. Docs pages are authored in a **custom markdown superset**
and render **real, live component demos that talk to a real server**.

> **Status: POC.** A plain Mix project (not `phx.new` yet) proving the pipeline end to end. The
> full vision, architecture, and roadmap live in **[`DESIGN.md`](./DESIGN.md)** — read it first.

## What it is

- **Custom markdown → live docs.** YAML front matter + `:::` container directives
  (`columns`/`col`/`card`/`callout`/`showcase`) + role-flagged code fences (`demo`/`run`/`example`)
  render to a page where a real web component mounts and runs.
- **Engine extracted.** The parser/renderer/behaviour live in the sibling library
  [`../keen-markdown`](../keen-markdown) (`KeenMarkdown`). keen-docs is its first consumer and adds
  only its **docs-specific extensions** (`lib/keen_docs/extensions/`: `demo`, `cdn_package`, `app`).
- **Content in Postgres.** A three-level content tree (`doc_set → doc_variant → document`) with
  content-addressed storage, package-version resolution, and full-text search — backed by stored
  SQL functions and raw Postgrex (no Ecto).
- **Browsable test harness.** A minimal Plug/Bandit web layer over the content functions.

## Quick start

```bash
make deps            # fetch dependencies
make poc             # build the standalone markdown POC → build/poc.html
make dev             # start the web test harness → http://localhost:4000
make demo            # read-only visualizer over the seeded content
```

The harness needs the database. Set it up once (needs VPN to `db-01.km8.local`), then regenerate
the typed wrappers:

```bash
# in ../keen-docs-database
make setup           # recreate the keen_docs DB (schema + const lookups + example content)

# back in keen-docs
make db-gen          # regenerate KeenDocs.Database.* from the live DB
make dev
```

`make` targets: `dev` · `iex` · `kill-port` · `db-gen` · `demo` · `poc` · `deps` · `test` · `clean`
(run `make help`).

## Architecture

- **Rendering pipeline** — `../keen-markdown` owns the parser (`directive_parser`), renderer,
  output regions (head/body/footer + toc/assets), context, and the `Extension` behaviour. Adding a
  block type means writing an extension, not editing the renderer. Generic blocks belong in the
  library; docs-specific ones (live demos, CDN, islands) belong here.
- **Database** — SQL functions in `../keen-docs-database` (managed by **debee**), typed Elixir
  wrappers generated by **db-gen** into `lib/keen_docs/database/`, executed through the thin
  `KeenDocs.Repo` (raw Postgrex). Deliberately **no Ecto**, mirroring `../keen-auth-permissions`.
- **Web** — `KeenDocs.Application` supervises `KeenDocs.Repo` + a Bandit/Plug router
  (`KeenDocs.Web.Router`), with `KeenDocs.Content` as the data API. Plug is the substrate Phoenix
  runs on, so promoting to `phx.new` + LiveView is additive.

### Key modules

| Path | Role |
|------|------|
| `lib/keen_docs/poc.ex` | Standalone-page shell (`KeenDocs.POC.build/2`) |
| `lib/keen_docs/extensions/` | Docs-specific renderer extensions (`demo`, `cdn_package`, `app`) |
| `lib/keen_docs/repo.ex` | Thin Postgrex connection (no Ecto) |
| `lib/keen_docs/database/` | db-gen-generated `KeenDocs.Database.*` wrappers (committed) |
| `lib/keen_docs/content.ex` | `use KeenDocs.Database` — the content API |
| `lib/keen_docs/application.ex` | Supervisor: Repo + Bandit |
| `lib/keen_docs/web/` | `Router` + `View` for the test harness |
